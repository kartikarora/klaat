Format Overview

Klaat processes structured document sources into interactive step-by-step tutorials. To ensure your content translates perfectly into the final codelab structure, you must follow specific formatting rules for your source files.

This guide explains the standard schema, YAML/Google Doc metadata fields, and markup conventions for all supported codelab content elements.

Codelabs are structured around Steps. Each step corresponds to a primary slide/page in the web tutorial. Underneath, content maps to blocks of code, text nodes, checklists, lists, or custom widgets.

Metadata Reference

Every codelab begins with a metadata block that defines configuration options like URL, authors, tracking ID, category, and target environments. These values configure the generated page metadata, tracking cookies, and catalogs.

Configuration Fields

YAML Field Requirement Data Type Default / Fallback Behavior Description
id Optional String Fallback: Sluggified summary. If summary is empty, defaults to untitled-codelab. Unique URL-safe directory identifier. Alphabetic characters, numbers, and dashes only.
summary Required String "" (Empty String) Short text description of the tutorial. Used in preview cards and index listings.
categories Optional List<String> [] (Empty List) Categories the tutorial belongs to. Used for indexing and filtering.
environments Optional List<String> ["Web"] Target environments where the tutorial should be made available.
status Optional List<String> ["Published"] Deployment status. Common values: Published, Draft, Deprecated.
authors Optional List<String> [] (Empty List) Author name(s) responsible for the codelab content.
feedback_link Optional String "" (Empty String) URL pointing to the repository issues page or feedback form. Renders as a footer action link.
analytics_account Optional String "" (Empty String) Google Analytics account/property tracking ID (e.g. UA-XXXXX-Y or G-XXXXXX).
tags Optional List<String> [] (Empty List) Searchable metadata keywords. Helps users find tutorials in preview portals.
source Optional String Fallback: Relative file path from the execution directory (e.g., src/tutorial.md). Indicates the original path of the resource. Used during the update command.
theme Optional String "" (Empty String) Optional styling theme flag. Passes down to the HTML templates for custom accent palettes.
duration Optional Integer Fallback: Calculated as the sum of all step durations (in minutes). The total duration of the tutorial. If specified, overrides the computed step durations.
image Optional String (URL) Fallback: Automatically extracts the URL of the first image element found in the tutorial content. Cover / hero image for catalogs. If not defined in the frontmatter, Klaat scans step contents and assigns the first image as the cover.
favicon Optional String (URL or path) Fallback: Default brand favicon icons (32x32, 16x16, apple-touch-icon). Custom favicon icon URL or file path for the exported codelab HTML page.
footer Optional String (HTML/text) Fallback: "Codelab generated using Klaat - A tool made by Kartik Arora" Custom footer HTML or text displayed at the bottom of each step in the tutorial.

Special Key Parsing Rules

List Properties (categories, tags, environments, status, authors)

Klaat parses list fields in two formats seamlessly:

  1. Comma-Separated String: Great for quick inline listing. 
    categories: Kotlin, Android, Server
  2. Standard YAML Block List: Preferred for long arrays. 
    categories:
  - Kotlin
  - Android
  - Server

Id Auto-Sluggification

If the id field is omitted, Klaat generates a URL-safe lowercase slug from the summary. Non-alphanumeric character sequences are compressed and replaced with dashes. For example:

Summary: "Kotlin: Async Programming & Coroutines!" 
Resulting ID: "kotlin-async-programming-coroutines"

Custom Metadata Pass-Through

By default, Klaat only maps the standard fields listed above. However, you can pass custom frontmatter variables down to templates or index documents using the -pass_metadata flag during export:

klaat export tutorial.md -pass_metadata "difficulty,reviewer,team"

In the frontmatter:

difficulty: Advanced
reviewer: Senior Engineer
team: DevRel

These values will be extracted, preserved, and injected into the template metadata context under the extraMetadata map.

Markdown Document

Markdown files are parsed with Flexmark and must conform to the structure below:

Markdown Structure Rules

  • Frontmatter Block: Must sit at the very beginning of the document enclosed inside triple dashes (---) as YAML fields.
  • Codelab Title: Must be a Heading 1 (e.g. # Title) directly following the YAML frontmatter.
  • Steps Headers: Each step is denoted by a Heading 2 (e.g. ## Step Title).
  • Step Duration: Directly beneath each Heading 2 step title, specify the expected time required using Duration: MM (minutes), Duration: HH:MM:SS / MM:SS (e.g. Duration: 0:01:30), or Duration: 0:00:00 (ignore) to exclude the step from the remaining total countdown.

Complete Markdown Example

---
id: intro-to-kotlin
summary: Learn basic syntax of Kotlin
categories: Kotlin
status: Published
authors: Kotlin Team
---

# Introduction to Kotlin

## Set up environment
Duration: 5

Let's configure IntelliJ IDEA...

## Write basic classes
Duration: 10

Here's an example:

```kotlin
class Person(val name: String)
```

Google Docs Document

Google Documents use special formatting rules to identify codelab elements. Klaat maps standard document styles to codelab nodes:

Document Structure

  • Metadata block: Begin your document with a two-column grid table. Key titles reside in the left column, values sit in the right column. Supported properties are the same as Markdown YAML fields.
  • Title: The Title format style or large text header.
  • Steps: Marked using Heading 1 paragraphs.
  • Step Durations: Written directly beneath the Heading 1 title as plain text in the format Duration: 5 (colored gray or formatted inside brackets is common).
  • Internal headings: Heading 2 maps to step subheadings, Heading 3 to lower sections.

Visual Element Mapping

Codelab Node Google Doc Format Element
Positive Info Box A single-cell table with a light green background.
Negative Info Box A single-cell table with a light orange/red background.
Regular Info Box A single-cell table with a black/light gray background.
Code Block A single-cell table using the Courier New font family.
Terminal Block A single-cell table using the Courier New font family with a black/dark background.

Text & Typography

Klaat supports standard rich formatting elements:

  • Bold: double asterisks **bold text**
  • Italic: single asterisks or underscores *italic text* or _italic_
  • Inline Code: backticks `var a = 1`
  • Links: [Link Title](https://example.com)
  • Action Buttons: Appending {.buttonPrimary}, {.buttonSecondary}, or {.button} renders an interactive pill button: 
    [Explore Live Demo](../demo/index.html){.buttonPrimary icon=play_arrow}

Code Blocks & Highlight

Klaat renders language-specific syntax highlighting for code blocks with one-click copy buttons.

Syntax Highlight Markdown

Append the language keyword immediately following the opening triple backticks:

```kotlin
fun greet(name: String) = "Hello, ${'$'}name!"
```
fun greet(name: String) = "Hello, ${'$'}name!"

With Source Code Filename

If you specify a file title immediately preceding the code block in bold, Klaat renders it with an attached header:

**Main.kt**
```kotlin
fun main() = println("Hello!")
```

Info Boxes (Alerts)

Info boxes are blockquote panels that call out suggestions, warnings, or time-sensitive critical information.

Special (Info/Tips)

Created in markdown using a blockquote block containing the {.special} metadata tag:

> This is a helpful tip! Use "special" infoboxes to draw attention to non-critical details. {.special}

This is a helpful tip! Use "special" infoboxes to draw attention to non-critical details.

Warning (Warnings/Alerts)

Created in markdown using a blockquote block containing the {.warning} metadata tag:

> Be careful! "Warning" infoboxes are for important information that the user must not miss. {.warning}

Be careful! "Warning" infoboxes are for important information that the user must not miss.

Critical (Errors)

Created in markdown using a blockquote block containing the {.critical} metadata tag:

> Do not hardcode credentials in your source code! {.critical}

Do not hardcode credentials in your source code!

Positive (Success)

Created in markdown using a blockquote block containing the {.positive} metadata tag:

> Congratulations! Your application is now running successfully. {.positive}

Congratulations! Your application is now running successfully.

Default

Created in markdown using any other blockquote block without specific metadata tags:

> This is just a default aside or quote.
> It will be styled with a neutral gray background.

This is just a default aside or quote. It will be styled with a neutral gray background.

Action Buttons

A link becomes a call-to-action pill button only when accompanied by a button tag attribute. Standalone links without button tags remain standard inline links. Klaat supports solid primary, outlined secondary variants, and custom Material Symbol icons:

  • {.buttonPrimary} (or shorthand {.button}): Renders a solid accent-filled pill button.
  • {.buttonSecondary}: Renders a sleek outlined accent button.
  • icon=<name>: Custom Material Symbol icon attribute (e.g. {.buttonPrimary icon=play_arrow} or {.buttonSecondary icon="launch"}).
  • Automatic Download Icon: Links whose text or URL references "download" or file extensions (.zip, .tar.gz) automatically display the download icon if no custom icon is specified.
# Primary Solid Button with Custom Icon
[Explore Live Demo](../demo/index.html){.buttonPrimary icon=play_arrow}

# Secondary Outlined Button with Email Icon
[Send Feedback](mailto:dev@kartikarora.me){.buttonSecondary icon=mail}

# Automatic Download Detection (on .zip or download links)
[Download Sample Archive](https://example.com/archive.zip){.buttonPrimary}

# Standard Inline Link (no button tag)
Visit the [Klaat Documentation](https://klaat.kartikarora.me/docs/index.html).

Kodelab Web Components (<kodelab-*>)

When Klaat exports a tutorial, it produces clean HTML5 powered by custom Web Components. These components handle step navigation, drawers, timers, survey persistence, and keyboard controls automatically.

Custom Element Hierarchy

The exported document uses custom elements defined under both <kodelab-*> and <klaat-kodelab*> tags:

Tag Name Attributes Description
<kodelab-codelab>
(or <klaat-kodelab>)		 id, title, environment, feedback-link, codelab-gaid Root component container. Orchestrates the drawer sidebar, step progress bar, title header, countdown timers, keyboard shortcuts (arrow keys), and URL hash routing.
<kodelab-step>
(or <klaat-kodelab-step>)		 label, duration, exclude-duration Encapsulates an individual step. The label appears in the drawer, and duration (minutes) feeds into the dynamic countdown clock.
<kodelab-survey>
(or <klaat-kodelab-survey>)		 survey-id Interactive questionnaire block that stores chosen options into localStorage.
<kodelab-analytics>
(or <klaat-kodelab-analytics>)		 gaid Google Analytics tracker recording step views and tutorial completion events.
